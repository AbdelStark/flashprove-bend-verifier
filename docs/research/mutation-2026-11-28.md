# Mutation test of the refusal checks, 2026-11-28

> Status: frozen

REQ-ASSURE-2 asks that each reachable refusal in the standalone verifier has a test that fails when that check is disabled. This report disables each check in turn, runs every suite against it, and gives each check no suite notices either a new test or a reason no input needs one. [Assurance contract](../spec/assurance.md) · [Outcomes](data/mutation/outcomes.json) · [Survivors](data/mutation/survivors.json)

## What ran

`scripts/mutate-refusals.py` finds every `require(COND, "NO: name")` in `src/` and rewrites one at a time as `require(Bool.or(COND, True{}), "NO: name")`. The condition is still evaluated, so linear values are still consumed, but the check always passes. Each mutant is built in its own copy of the checkout and run against these suites, fastest first, until one fails:

`standalone-test`, `plan-test`, `public-input-test`, `standalone-rejections`, `request-claims-test`, `fuzz` (64 cases), `standalone-extended`, `stages-test`, `test test-native`.

```sh
make standalone oracle
python3 -B scripts/mutate-refusals.py -j 6 --out mutants.json
```

The sources at `51d3604` hold 183 such checks. The runs were Slurm jobs 7811 (all sites that survived an earlier pass, at `021fadc`) and 7816 (all sites any earlier pass reported caught, at `51d3604`). Both ran on one node with 28 Xeon cores under Linux 6.8 and Ubuntu clang 18.1.3. The two revisions differ only in tests and in twelve definitions nothing called, so a check that survived at `021fadc` survives at `51d3604`. Job 7816's Bend source digest was `0a20844dd818a400aa65f4f6d2e38125237dc4974db85f501fecb4ee0a1e9585`. One site, `KL-length`, was rerun locally after its test was added.

## A harness fault inflated the first score

The first pass (job 7800) reported 76 checks caught. Mutants running in parallel each ran `make upstream` against the shared upstream checkout and raced on its git lock. The suite that lost the race failed, and the harness counted that failure as a kill. The clearest sign was a check inside a definition nothing calls, reported caught; run alone, it survived every suite. The harness now passes `-o upstream` to make, and job 7816 kept every mutant's log. Of the 78 sites it re-tested, 40 survived. A survival cannot come from this fault, so the earlier survivor list stood.

Each survivor's reason, with the file and line it rests on, is in the [survivor list](data/mutation/survivors.json).

## New tests

Four checks guarded inputs that no test refused by name. Each now has one, and each mutant now dies:

| Check | Input | Without the check |
| --- | --- | --- |
| `noncanonical-element` (`round_io.bend:77`) | PROOF with 2^64−1 in a reply coordinate | Refused later under another name; nothing after this check re-tests canonical encoding, so a prover who recomputes the transcript could encode x+p |
| `public-table-length` (`policy_tables.bend:30`) | `softmax-12-8.bin` missing its three trailing zero bytes | Accepted: the cut file packs to the same words and digest |
| `KL-length` (`policy_scales.bend:57`) | `KL.bin` missing its trailing zero byte | Accepted, for the same reason |
| `plan-length` (`wire_reader.bend:67`) | `key.bin` one byte short | Refused later as `opening` |

The two table cases are not soundness faults, since the values read stay the same, but they accepted malformed public files. The `noncanonical-element` case is the one that matters for soundness.

## Limits

The 142 reasons come from reading the code, not from running inputs. Only `trailing-data` at `wire_reader.bend:145` was confirmed by a run: with it disabled, a key file with 1 to 5,000 extra bytes was still refused by the twin check under the same name. The self-check and shadowed reasons assume the digests resist collisions. The negligible events have no test; covering them needs a probe that overrides one challenge, as `--changed-range-target` does for the key stage. One self-check, `request-stored-copy`, holds only because the spec rules out a PROOF that changes during a call.
