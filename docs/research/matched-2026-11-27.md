# Bend, C++ and Lean on the same cores, 2026-11-27

> Status: frozen

Issue #22 asked for one set of matched measurements of the optimized verifier: standalone Bend at one worker and at a tuned count, `cp_verify` with one request-stage thread and with sixteen, and Lean OnBytes. This report gives them for one build on both hosts, with the profile that explains the remaining gap to C++. [Performance contract](../spec/performance.md)

The build is `74b3054`: main at `434ddc7`, with the faster powers of two from #60, plus a benchmark option that sets `cp_verify`'s threads. Its Bend source digest is `02153c1fc269ad77a8d5a1ec101b905ba14181e034a5f5d57e1059a277e1305f`.

- The Xeon is a Platinum 8480CL in one Slurm job (7808) with 16 dedicated physical cores, under Linux 6.8 with Ubuntu clang 18.1.3. Each pairing is pinned to one logical CPU per core, either 1 core or 16. One other job held 2 CPUs on the node.
- The M4 Max is under macOS 26.6.2 with Apple Clang 21.0.0, unpinned.

Every figure is the median of three alternating calls on the full-size exact-match proof, after one verified warmup each. Every call matched the four published closing lines. [Raw results](data/matched/)

## `cp_verify -j 1` is not a single-thread program

`-j` sets the threads of C++'s request stage only. With more cores available, the other stages use them too:

| Host | C++ `-j 1` on | Wall | CPU |
| --- | --- | ---: | ---: |
| Xeon | 1 core | 20.967 s | 20.94 s |
| Xeon | 16 cores | 18.562 s | 20.94 s |
| M4 Max | all 16 cores | 7.895 s | 9.49 s |

So a comparison with "one-thread C++" depends on the cores C++ is given. The tables below say which.

## Where Bend's time goes

The request stage takes 18.9 of 21.3 s of a full-size call with one worker on the M4. In a sample of that call, extension-field products take 21% (`E3.mul` 17%, `E3.scale` 4%). Reference counting and freeing take 37% (`span_fade` 15%, `term_drop` 13%, `rfc_wrap` 8%), and closure application takes 4%. C++ keeps its vectors in flat arrays of machine words, with no reference counts. The counting is the largest single difference, and it is the work #15 tracks. With more workers, Bend's time stops falling at about 8: the transcript fixes the order of the request's transitions, and only the local equations between them run in parallel (#20).

## Requirements

- **REQ-PERF-3 is met** on both hosts. With one worker, Bend takes 1.78× (Xeon) and 2.13× (M4) as long as C++; the budget is 8×. Its peak memory is 1.89 GiB; the budget is 7 GB.
- **REQ-PERF-4 is open.** With 16 workers, Bend takes 1.12× (Xeon) and 1.19× (M4) as long as C++ `-j 1` given the same cores. On the Xeon, Bend's 20.81 s at 16 workers is below C++'s 20.97 s pinned to one core. That pinned run is the only truly single-thread C++ figure, but it comes from a different pairing.
- **REQ-PERF-6 is met:** 4.58× faster than Lean OnBytes on the Xeon.
